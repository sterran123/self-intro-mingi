# 김민기 — 나를 소개하는 사이트, 그리고 계속 새로 쓰는 장치

공개 자기소개 사이트 + 새 기록을 넣으면 사이트의 숫자와 문단 후보를 다시 만들어 주는 장치.

## 구조

- `docs/ (= GitHub Pages 루트)` — 정적 사이트. `index.html`이 본체, `data.json`의 숫자를 카드로 그린다. `docs/`에 이력서·자기소개서·경력기술서, `works/`에 대표작 파일.
- `input/` — 장치가 읽는 원자료. `ritual.md`(리추얼 기록), `assignments.json`(과제 목록·상태), `attendance.json`(출석 수치 — 비어 있으면 해당 숫자는 뜨지 않음).
- `tools/refresh.js` — 장치 본체. 입력을 읽어 숫자를 다시 세고 능력별 문단 후보를 뽑는다.
- `output/candidates.md` — 사람이 검토하는 후보 목록. 승인한 문장만 이야기에 반영한다.

## 장치 돌리는 법 (세 단계)

1. `input/`에 최신 리추얼 기록(마크다운), 과제 목록, 출석 수치를 넣는다.
2. `node tools/refresh.js`를 실행한다 (Node.js만 필요, 외부 호출·키 없음).
3. `docs/ (= GitHub Pages 루트)data.json`이 새 숫자로 바뀌고, `output/candidates.md`에 날짜·근거가 붙은 능력별 문단 후보가 나온다.

같은 입력이면 항상 같은 결과가 나온다 — AI 호출 결과를 쓰지 않고 파일만 파싱해 계산하기 때문이다. 출력의 `input_sha256` 필드로 어떤 입력에서 나온 결과인지 확인할 수 있다.

## 사이트

- 첫 화면: 이름(김민기), 한 줄 소개("무너진 밤을 견디고, 아침의 한 줄로 다시 서는 사람"), 섹션 입구.
- 이야기: 날짜가 있는 세 장면 — 2026-08-24(고난) → 2026-10-08(다시 일어난 날) → 2026-10-12(더 나아진 지금). 자기조절력·대인관계력·자기동기력이 각 장면에 드러난다.
- 숫자: `data.json`의 수치가 출처와 함께 표시된다. 실천율 카드는 "못 했다고 적은 날"과 짝지어져 있다.
- 대표작: 과제 10 논문(파일로 게재), 과제 13 앱 자리(예정 표시).
- 문서: 이력서·자기소개서·경력기술서 다운로드.

## 주의

- 사이트·문서·장치 어느 곳에도 본인(김민기) 외 다른 사람의 실명·연락처, 비밀값이 없다. 리추얼 기록 원본의 동료 칸은 이미 "(이름 가림)"으로 가려져 있다.
- 새 기록을 넣고 장치를 돌려도 문단 '후보'만 나온다 — 사이트 이야기는 내가 승인한 문장만 바꾼다.
