# 경력기술서 — 김민기

13주 리추얼 과정 동안 수행한 과제를 능력·상황·행동·결과로 정리했습니다. 능력은 자기조절력(S), 대인관계력(R), 자기동기력(M)으로 표시합니다.

## 과제별 기술

**과제 10 · 첫 논문 — AI 반복 교정의 수렴** `M·S`
- 상황: AI가 글을 여러 번 고칠 때 실제로 얼마나 고치는지 가설을 직접 검증하고 싶었다. 측정이 주관에 오염되지 않게 할 방법이 관건이었다.
- 행동: 고침량을 문자 편집 거리 비율로 정의해 기계가 세게 만들고, 텍스트 10편 × 3회차 = 30건 실험을 설계·실행. 지시문을 제한한 대조 조건 B를 추가해 변수를 분리했다.
- 결과: 회차별 변경률 6.91%→1.49%→0.62%의 수렴을 확인하고, 편집 자유도가 수렴을 결정함을 입증. 원자료·분석 스크립트·재현 방법까지 포함한 KCI 양식 논문 완성.

**과제 11 · 3만 자 장편소설 + 웹 뷰어** `M·S·R`
- 상황: 내 삶을 소재로 한 장편을 완결까지 쓰고, 읽는 사람이 편한 형태로 배포해야 했다.
- 행동: 12개 장·4개 결말의 분기 구조를 설계하고 58,800자 원고를 완성. 자동 진행·선택지 정지·속도 조절·삽화 13점을 갖춘 채팅형 웹 뷰어를 직접 구현해 GitHub Pages에 배포했다.
- 결과: 로그인 없이 열리는 완결 소설 사이트. 구조·중복·금지구·비밀값 검사를 통과한 정본 원고.

**과제 6–7 · 플랜두씨 다이어리** `S·M`
- 상황: 내 계획과 실제의 차이를 스스로 볼 수 있는 기록 앱이 필요했다.
- 행동: 계획·실제를 나란히 담는 화면을 만들고, 두 번째 버전에서는 인증을 붙이되 "어떻게 붙였는지"를 문서로 설명했다.
- 결과: 계획 대비 실제를 보는 앱 완성 + 인증 설계 설명 문서.

**과제 8 · 패스키 인증 페이지** `S·M`
- 상황: 비밀번호 없이 본인만 들어가는 페이지를 만들어 실제 인증 흐름을 이해해야 했다.
- 행동: 소개 페이지에 패스키(WebAuthn) 등록·로그인 흐름을 직접 구현했다.
- 결과: 비밀번호 없는 로그인이 동작하는 공개 페이지.

**과제 5 · 대화가 끊겨도 이어지는 프로젝트** `M·R`
- 상황: 세션이 끊기거나 대화가 중단돼도 작업 맥락이 남아야 하는 문제를 다뤘다.
- 행동: 상태를 저장하고 이어가는 구조를 설계·구현했다.
- 결과: 중단 후 복귀해도 맥락이 이어지는 프로젝트 완성.

**과제 4 · 오늘의 진짜 정보판 — 데이터가 안 올 때** `S`
- 상황: 외부 데이터가 오지 않을 때 정보판이 어떻게 행동해야 하는지 정직하게 설계하는 과제였다.
- 행동: 데이터 부재 상태를 화면에 드러내고 폴백을 두었다.
- 결과: "데이터 없음"을 거짓으로 메우지 않는 정보판 UI.

**과제 9 · 나를 말하는 에이전트** `R·M`
- 상황: 22일 리추얼 기록에서 내 강점과 이야기를 찾아 말해주는 에이전트가 과제였다.
- 행동: 기록을 구조화해 강점·일화를 추출하는 흐름을 설계했다.
- 결과: 사이트 이야기의 사실 기반이 된 서사 문서.
